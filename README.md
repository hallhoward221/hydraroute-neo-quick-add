# HydraRoute Neo Quick Add

Неофициальное расширение Chrome/Edge (Manifest V3), которое добавляет текущий сайт в выбранную папку правил **HydraRoute Neo** одним кликом.

- Выбрали папку в настройках один раз.
- Кликнули иконку на сайте — домен ушёл в правило.
- HRweb сохранил `domain.conf` и перезапустил `hrneo`.
- Следующее добавление доступно через **10 секунд**.
- Опционально: перед добавлением домен проверяется в реестре РКН через 2whois.ru. Если его там нет — правило не создаётся.

## Требования

- Роутер Keenetic с установленным **HydraRoute Neo** и **HRweb**.
- HRweb доступен по адресу вида `http://192.168.1.1:2000`.
- Chrome или Edge с поддержкой Manifest V3 (проверено на Edge 156 / Chromium 156).
- Версия HRweb, на которой проверялось: **1.68.0**. Внутренний API HRweb недокументирован и может измениться в следующих версиях.

## Установка

1. Откройте `chrome://extensions` (или `edge://extensions`).
2. Включите **Режим разработчика**.
3. Нажмите **Загрузить распакованное расширение**.
4. Выберите папку `HydraRouteNeo-Extension`.
5. Откройте настройки расширения (иконка → «Настройки» или правая кнопка → «Параметры»).

> Chrome/Edge может показать предупреждение «Читать историю просмотров». Это разрешение `tabs`; оно нужно только для чтения адреса активной вкладки, включая состояние загрузки и страницу ошибки. Содержимое сайтов расширение не читает.
>
> Также будет запрошен доступ к `2whois.ru` — он нужен только для проверки домена в реестре РКН.

## Настройка

1. Укажите адрес HRweb, например `http://192.168.1.1:2000`.
2. Введите логин и пароль администратора Keenetic.
3. Нажмите **«Проверить и загрузить папки»**.
4. Разрешите расширению доступ к адресу роутера в появившемся окне Chrome.
5. Выберите карточку политики (например, `Youtube`) и при необходимости группу внутри неё.
6. Нажмите **«Сохранить»**.

Пароль хранится локально в `chrome.storage.local` и используется только для автоматического входа в HRweb. Он не отправляется никуда, кроме указанного адреса роутера.

## Проверка РКН

В настройках есть галочка **«Проверять сайт в реестре РКН перед добавлением»** (по умолчанию включена).

Как это работает:

1. Расширение открывает фоновую вкладку `2whois.ru/rkn/?data=<домен>`.
2. Content script читает результат:
   - «Есть совпадение в реестре РКН» — домен найден;
   - «В реестре не найден» — домен не найден;
   - «Проверяем, что вы не робот» / «Я человек» — нужна проверка.
3. Если 2whois просит подтверждение, вкладка выводится на передний план. Нажмите **«Я человек»** — дальше расширение продолжит автоматически.
4. Если домен найден — он добавляется в HRneo.
5. Если домен не найден — расширение пишет «В РКН не найден. Добавлять не нужно» и **не** сохраняет правило.
6. Результат кэшируется на 24 часа.

Проверяется сначала точный домен (`music.youtube.com`), затем, если он не найден, корневой (`youtube.com`). Если найден корневой, в HRneo всё равно добавляется тот домен, который был в адресной строке.

В контекстном меню есть:

- **«Добавить без проверки РКН»** — принудительно добавить, не обращаясь к 2whois;
- **«Проверить текущий сайт в РКН»** — только проверить, без добавления.

Очистить кэш проверок можно в разделе «Диагностика» → «Очистить кэш проверок РКН».

Если вкладка 2whois осталась в фоне, после проверки расширение закрывает её автоматически. Если вкладка была выведена на передний план (например, для подтверждения «Я человек») и вы её просматриваете, она останется открытой.

> Капча/антибот-проверка 2whois не обходится автоматически. Если 2whois временно ограничил доступ («Доступ ограничен»), расширение сообщит об ошибке и не будет добавлять домен. В этом случае можно повторить позже или использовать «Добавить без проверки РКН».

## Использование

- Откройте сайт и нажмите на иконку расширения.
- Можно кликать сразу после нажатия Enter, не дожидаясь загрузки страницы: расширение берёт `pendingUrl`.
- Если страница загрузилась с ошибкой (например, DNS), Chrome сохраняет URL вкладки, и расширение добавляет именно его.
- Домен добавится в выбранную папку; появится уведомление.
- Если включена проверка РКН и домен не найден, добавления не будет.
- На иконке будет обратный отсчёт 10 секунд — в это время добавление заблокировано, потому что HRweb перезапускает `hrneo`.
- Повторный клик во время выполнения операции игнорируется, чтобы не отправить два сохранения.
- Если домен уже есть в правилах, расширение не создаст дубликат и покажет, где он находится.
- Правая кнопка → **«Отменить последнее добавление»** — откат последней операции (в течение 5 минут, если правила не менялись).
- Горячая клавиша по умолчанию: `Alt+Shift+A`.

### Что считается доменом

По умолчанию добавляется **точный адрес сайта**:

```text
gemini.google.com  →  gemini.google.com
music.youtube.com  →  music.youtube.com
www.example.co.uk  →  www.example.co.uk
```

Это безопаснее для Google, Cloudflare и других общих доменов: случайно не добавится `google.com` вместо `gemini.google.com`.

В настройках можно включить **корневой домен**:

```text
music.youtube.com  →  youtube.com
www.example.co.uk  →  example.co.uk
foo.github.io      →  foo.github.io
```

Если в выбранной папке уже есть родительский домен (например, `youtube.com`), расширение не будет добавлять `music.youtube.com`: оно сообщит, что домен уже покрыт правилом.

Префикс `www.` по умолчанию **не** убирается; это можно включить отдельно.

IP-адреса и локальные адреса (`localhost`, `.local`) пока не поддерживаются.

Браузер не отдаёт расширению текст, который вы только печатаете в адресной строке, но ещё не отправили. Адрес становится доступен после нажатия Enter / начала перехода. Это ограничение Chrome/Edge, а не расширения.

## Как это работает

1. Расширение входит в HRweb через `POST /login` (логин/пароль роутера).
2. Читает конфигурацию через `POST /api` → `config.get`.
3. Находит выбранную карточку/группу в `domain.conf`.
4. Аккуратно вставляет домен в нужную строку, не перестраивая остальные правила.
5. Сохраняет через `config.save`; HRweb записывает файл и перезапускает `hrneo`.
6. Ставит блокировку на 10 секунд.

Внутренний API HRweb проверяет `Origin`/`Referer`: запросы с `chrome-extension://` он отклоняет. Расширение использует `declarativeNetRequest`, чтобы удалить эти заголовки **только для своих POST-запросов к указанному роутеру**. Обычные сайты это не затрагивает.

HRweb сохраняет весь `domain.conf` целиком. Если в этот момент в HRweb открыт черновик с несохранёнными изменениями, возможен конфликт. Не держите несохранённые правки в HRweb во время добавления через расширение.

## Безопасность

- Пароль роутера хранится локально в профиле браузера. Это не аппаратное шифрование; любой, кто имеет доступ к профилю, может его прочитать.
- По возможности используйте отдельную учётную запись администратора Keenetic для расширения.
- Не устанавливайте расширение с сохранённым паролем на чужой компьютер.
- Расширение запрашивает доступ только к адресу роутера, который вы указали.
- Разрешение `tabs` используется только для чтения адреса активной вкладки, включая `pendingUrl` во время загрузки; доступ к содержимому сайтов расширение не запрашивает.
- При проверке РКН домен отправляется на `2whois.ru` — это единственный сторонний сервис, который используется расширением. Другие данные туда не передаются.
- Расширение не отправляет данные на другие сторонние серверы и не содержит аналитики.
- При изменении адреса правило DNR заменяется; разрешение на старый адрес можно отозвать в настройках доступа расширения.
- Для публикации в Chrome Web Store потребуется обосновать использование `cookies`, `declarativeNetRequest` и удаление `Origin`; для личного использования достаточно загрузки распакованного расширения.

## Ограничения

- Внутренний API HRweb недокументирован; после обновления HRweb расширение может потребовать правок.
- HTTPS с самоподписанным сертификатом может не работать: `fetch` из расширения не игнорирует ошибки сертификата.
- Проверка РКН зависит от доступности `2whois.ru` и его антибот-проверки. При «Доступ ограничен» или таймауте домен не добавляется; используйте «Добавить без проверки РКН» или повторите позже.
- 2whois может ограничивать частоту запросов. Результаты кэшируются на 24 часа.
- Каждое добавление перезапускает `hrneo`; поэтому стоит блокировка 10 секунд.
- IP-адреса и CIDR пока не поддерживаются.
- Нельзя добавить домен в несуществующую карточку: создайте её заранее в HRweb.
- При нескольких группах с одинаковым описанием выбирается первая; для точного выбора используйте индекс группы в настройках (сохраняется автоматически).

## Разработка и тесты

В папке `dev/` есть mock-сервер HRweb и тесты:

```bash
python dev/mock_hrweb.py --port 8765
# логин: admin / secret
```

- `dev/test.html` — тесты парсера `domain.conf`, вставки домена и определения корневого домена. Откройте в браузере.
- `dev/api_test.html` — тест клиента HRweb против mock-сервера. Откройте `http://127.0.0.1:8765/test`.
- `dev/cdp_test.py` — интеграционный тест расширения через CDP (Edge + тестовая копия с `host_permissions`).
- `dev/cdp_options_test.py` — проверка страницы настроек.

Mock-сервер не является настоящим HRweb и не должен использоваться на роутере.

## Структура

```text
manifest.json          манифест MV3
background.js          service worker: клик, API, DNR, cooldown, undo
options.html/css/js    страница настроек
lib/parser.js          разбор и правка domain.conf
lib/hrweb.js           клиент внутреннего API HRweb
lib/domain.js          определение корневого домена (tldts)
lib/settings.js        настройки и storage
lib/util.js            утилиты
lib/tldts.umd.min.js   Public Suffix List (MIT)
icons/                 иконки
dev/                   mock-сервер и тесты
```
